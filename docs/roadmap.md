# 下一步

按收益/风险排序。前两项是"能不能交付"的问题，后面是"好不好用"。

## 1. 固定 `--rect` 的口径（阻塞项）

现在工具里还留着一条"自动拟合"的兜底路径，实测会给出 `sx = 0.05` 这类明显错误的缩放，
表现为：旧图没盖住、新图错位、高度不对。计划**直接删掉**，强制要求 `--rect`。

生成端在把绘图放进 PDF 时就知道那个框，按 **PDF 点**记下来传给工具即可：

```
--rect  x0,y0,x1,y1     ← 绘图框（左上、右下）
--cover a0,b0,a1,b1     ← 要擦掉的单元格内部（通常比 rect 略大）
```

需要确认一件事：这个框对应的是 SVG 的 **viewBox** 还是**内容包围盒**。
两者在本项目的样本里几乎相同（内容几乎铺满 viewBox），但仍是需要明确的契约。

## 2. 端到端断言（回归保护）

现在每改一次都是"渲染 + 肉眼 + 像素统计"。应该固化成脚本：

| 断言 | 目标 |
|---|---|
| 位图对象数 | `0` |
| 文件大小 | < 原件的 5% |
| 文字字符数 | ≥ 原件（标注没丢） |
| 600 dpi 墨量差 | 每个区域 < 2% |
| 页面数 / 页面尺寸 | 不变 |

用 PyMuPDF 写一个 `tests/check.py`，CI 里跑（样例文件不入库，用环境变量指定路径）。

## 3. 字体

SVG 里没有字体文件，现在用 Helvetica 兜底，和报告自带的 Calibri 有明显差异。
报告本身嵌了 37 个 Calibri 子集，可以**直接复用其中一个**写标注，做到字形一致。
需要：从报告的 `/Font` 里挑一个匹配的（按字重），用它的编码表写字符串。

## 4. 旧文字层清理

现在是"覆盖"：旧标注仍在文本层（可选中、可提取），视觉上看不见。
若要干净，需要在旧内容流里**裁掉落在 cover 区域内的文字算子**（`BT…ET` 块）。
风险：会动到整页的内容流，需要逐 token 判断位置，工作量大、收益中等。

## 5. 自动定位（兜底，不是主线）

表格竖线检测是可靠的（样本里 8 条竖线一次找全）。可以作为"没给 `--rect` 时的提示"：
先算出单元格，再要求确认。**不要**再尝试从填充/套管反推精确仿射。

## 6. 多列 / 批量

目前只处理单个 WBG 列。同一份报告里其它列可能也有类似图形（或未来会有）。
`apply` 的核心是 `emitSvg(transform)`，天然可以循环多次：

```
for each (svg, rect) in plan:  emitSvg(...)
```

配套需要一个 `plan.json`（哪个 svg 放哪个框），由生成端产出。

## 7. 上游修复（最彻底）

如果生成端可改，最好的方案是**不让浏览器栅格化**：

- 让那个元素走矢量导出（`svg2pdf` / librsvg 之类，把 pattern 映射成 PDF tiling pattern）；
- 或者干脆不画真图，只画一个占位矩形 + `/PieceInfo`（记录 svg 文件名与目标框），
  由后处理"对号入座"。

前者让 PDF 一开始就是矢量的；后者把"推断"变成"契约"。两者都比事后修复便宜。
